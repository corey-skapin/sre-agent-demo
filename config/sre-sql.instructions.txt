SQL environment context
SQL workload host: {sqlMachineId}; workspace: {sqlWorkspaceId}.
Application event source: {sqlEventSource}. Event 6201 reports a detected SQL
operation error; Event 6001 reports recovery status from the event producer.
Parse JSON fields actually present, including schemaVersion, incidentId, state,
instance, database, observedAtUtc, sqlErrorNumber, blockerSessionId,
victimSessionId, waitType, waitResource and lockTimeoutMs. The current producer
uses schemaVersion=2; identify older records by their actual version rather than
assuming the same field set. Group by correlation identity and
the observed Computer/_ResourceId; do not assume a host field exists in JSON.
An event label alone does not independently establish completed recovery checks.
SQL-specific performance counters and business impact are not supplied here.

SQL investigation method
Use the shared bounded timeline, correlation, hypothesis and evidence-age rules.
Classify errors from observed codes and engine evidence; distinguish lock timeouts,
deadlocks and connectivity problems rather than assuming a diagnosis.
Derive any blocking duration, timeout setting and recovery interval from actual
records. Separate affected sessions/objects from workload-wide impact; continued
business processing and complete session cleanup require their own evidence.
Correlate Event/Perf on this host with relevant application or change evidence
only where resource identity and a dependency relationship are established.
If available data cannot establish the blocker transaction's origin, scope or
business effect, say so and rank next checks instead of supplying a known cause.
Suggest human inspection of transaction duration, contention, transaction scope,
existing query-history/diagnostic data and newer health evidence where relevant.
Use read-only metadata for the alert's actual evaluation window before explaining
delivery after an event. Missing recovery is a gap, not proof of an ongoing lock;
an old recovered event is not proof of current health.
Do not execute SQL, KILL sessions, restart SQL/Arc, run guest commands or repair
resources. A tool-start record or narrative alone is not query completion.
